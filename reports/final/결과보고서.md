## 2. 추진 배경과 목표

### 해결하려던 문제

1. **채널 분산** — 비교과·공모전 공지가 학교 홈페이지, 사업단 홈페이지, 대학·사업단 인스타그램에 나뉘어 올라온다.
2. **마감일이 본문·포스터 속에 있음** — 제목만 봐서는 신청 기간을 알 수 없고 글이나 이미지를 직접 읽어야 한다.
3. **캘린더 수동 입력** — 확인한 일정을 다시 손으로 캘린더에 옮겨야 해서 놓치기 쉽다.

### 목표 (활동계획서 기준)

- **최종 목표**: 대전대학교 학생 누구나 이 레포를 보고 자기만의 비교과 캘린더 자동화를 만들 수 있게 한다.
- **세부 목표**
  1. 활동 기간 내 대전대학교 공식 인스타그램과 사업단 채널 대상 자동화 완성
  2. 실제 공지 30건 기준 마감일 정리 정확도 90% 이상
  3. 팀 외부 학생 5명이 레포 안내만으로 자기 캘린더 자동화 구현

## 3. 수행 결과

### 3.1 만든 것

공지가 들어오는 길을 세 가지로 만들고, 세 경로가 **같은 추출 프롬프트**로 정리하게 했다.

| 기능 | 내용 | 위치 | 상태 |
|---|---|---|---|
| 공통 추출 프롬프트 | 공지 여부 판별, 행사명·신청 기간·마감일·대상·신청 방법 추출 | `prompts/extract_notice.md` | ✅ |
| AI 정리 모듈 | Gemini로 공지 본문(+포스터)을 정리하고 형식 검사 | `src/magami/extract.py` | ✅ |
| 프롬프트 방식 | 설치 없이 AI 채팅에 붙여넣어 사용 (인스타그램 게시물 포함) | `prompts/README.md` | ✅ |
| 크롬 확장 프로그램 | 사용자가 연 공지에서 버튼 한 번 → 결과 확인·수정 → 구글 캘린더 추가·내 마감 목록 | `extension/` | ✅ |
| 매일 자동 실행 | 허용된 사업단 메인 공지 칸을 하루 1회 확인 (GitHub Actions) | `.github/workflows/daily.yml` | ✅ |
| 새 공지 이메일 알림 | 새로 올라온 공지를 이메일로 알림 | `src/magami/notify.py` | ✅ |
| 메인 공지 칸 수집기 | 제목·날짜·링크만 수집, `robots.txt` 확인 | `src/magami/collect_homepage.py` | ⏳ |
| 공지 체크 화면 | 원문 링크와 함께 공지를 보고 체크 | `app/` (Streamlit) | ⏳ |
| 구글 캘린더 일괄 등록 | 체크한 공지만 캘린더에 등록 | `src/magami/calendar_sync.py` | ⏳ |
| 정확도 평가 | 정답 자료와 비교해 마감일 정확도 계산 | `tests/`, `data/ground_truth/` | ⏳ |
| 설치 안내서·에이전트용 안내 파일 | 레포만 보고 설치, "이 레포 안내대로 설치해 줘" | `docs/`, `AGENTS.md` | ⏳ |

### 3.2 동작 방식

```
 ① 자동 (하루 1회)              ② 크롬 확장 프로그램            ③ 프롬프트 방식
 허용된 메인 공지 칸의           사용자가 연 공지에서            링크·본문·캡처를
 제목·날짜·링크 수집             버튼 한 번                      AI에 붙여넣기 (인스타그램 포함)
 → 새 공지 이메일 알림
          └──────────────────────────┬──────────────────────────┘
                                     ▼
                  공통 AI 정리 (Gemini + prompts/의 추출 프롬프트)
                                     ▼
                  공지 체크 화면 (원문 링크와 함께 확인)
                                     ▼
                  체크한 공지만 구글 캘린더 등록
```

## 10. 수집 원칙 준수

- 홈페이지는 `robots.txt`와 이용약관을 확인한 범위에서만 수집하고, 확인 결과를 채널별·날짜별로 [`docs/collection-policy.md`](../../docs/collection-policy.md)에 기록했다.
- 공지 목록·본문은 자동 수집하지 않고, 자동 수집은 하루 1회로 제한했다.
- 원문 전체를 저장하지 않고 정리한 정보와 원문 링크만 남긴다. 게시물 속 개인정보는 저장하지 않는다.
- API 키는 GitHub Secrets(자동 실행)와 사용자 브라우저(크롬 확장)에만 둔다.

## 11. 한계와 향후 계획

- **인스타그램 자동 수집**: 공식 API(Business Discovery) 연동은 향후 과제로 남겼다.
- **홈페이지 본문 자동 수집**: 학교 허가가 있어야 가능하다. 지금은 크롬 확장과 프롬프트 방식으로 대신한다.
- **크롬 확장의 학교 이용 기준**: 사용자가 연 공지를 버튼으로 읽는 방식도 학교 기준에서 허용되는지 별도 확인이 필요하다.
- **API 키 없이 쓰기**: 크롬에 내장된 AI(Gemini Nano)를 쓰면 키 발급 없이 확장을 쓸 수 있어, 설치 장벽을 낮출 수 있다.
- **디스코드 알림**: 알림 함수를 하나 더 붙이는 구조라 쉽게 추가할 수 있다.
- ⏳ 평가에서 나온 개선점
